# Итоговый проект — ValutaTrade Hub

> СГЕНЕРИРОВАНО ИИ!(При моём активном участии :D)

Дисциплина: «Программирование на Python», группа М26-555. Консольное приложение для виртуального портфеля фиатных и криптовалют. Реальных покупок, переводов и подключения к биржевым кошелькам здесь нет.

## Текущее состояние

Реализованы модели, иерархия валют, исключения, Singleton-настройки, JSON-хранилище и все восемь команд CLI. Parser Service получает настоящие курсы из обоих API, сохраняет кэш и историю, обрабатывает частичный отказ источников. Логи операций и парсера сохраняются в JSON с ротацией. Впереди финальная сверка, проверка дистрибутивов и локальная демонстрация; версия пока не передана автору на итоговое ревью.

По согласованию с автором выбрана пошаговая модель CLI из задания: `buy` увеличивает баланс выбранной валюты, `sell` уменьшает его, USD используется для оценки. Произвольного стартового баланса и автоматического списания/зачисления на USD-кошелёк нет.

## Запуск

Нужны `uv` и Python 3.12. Для локальной работы закреплён Python 3.12.10. Из корня проекта:

```powershell
uv sync --locked
uv run valutatrade
uv run ruff check .
uv run ruff format --check .
```

`uv` создаёт `.venv` и устанавливает зависимости. Команда `valutatrade` открывает интерактивную сессию; `help` показывает команды, `exit` завершает её. Также работает `uv run --env-file .env python main.py`. Для реальных фиатных курсов запускайте с загрузкой `.env`: `uv run --env-file .env valutatrade`.

## Сервисы и ключи

Для курсов используются ExchangeRate-API и CoinGecko. Отдельная биржа, платный тариф, сервер базы данных и Docker для начала работы не нужны.

Создайте локальный `.env` из шаблона, если его ещё нет:

```powershell
Copy-Item .env.example .env
```

Если `.env` уже существует, не перезаписывайте его. Заполните только значения после знака `=`:

```dotenv
EXCHANGERATE_API_KEY=
```

`EXCHANGERATE_API_KEY` — ключ вашего аккаунта ExchangeRate-API. CoinGecko работает только в публичном режиме без ключа, как разрешено заданием и выбрано автором. Продолжать регистрацию, получать Demo-ключ или покупать Pro-тариф не нужно.

Файл `.env` исключён из Git и сборки. В Git хранится только пустой `.env.example`. Не отправляйте ключи в чат, README, скриншоты и логи.

Для загрузки настроек из `.env`:

```powershell
uv run --env-file .env valutatrade --check-config
```

Проверка выводит только наличие ключей. Она не отправляет запросы и не подтверждает действительность ключа. При запуске установленного пакета без `uv` переменные окружения нужно передать отдельно.

## Структура

```text
valutatrade_hub/
├── core/            # модели, валюты, исключения и бизнес-операции
├── infra/           # настройки и JSON-хранилище
├── parser_service/  # конфигурация и будущий сбор курсов
├── cli/             # командный интерфейс
├── logging_config.py
└── decorators.py
main.py
pyproject.toml
uv.lock
```

Пакет расположен в корне, как в ТЗ. Локальные `data/`, `logs/`, `.venv` и настройки редактора в репозиторий не попадают. Пока созданы пустые локальные JSON-файлы; демо-пользователей, паролей и вымышленных курсов нет.

## Реализованные блоки задания

1. Модели `User`, `Wallet`, `Portfolio`; `register`, `login`, `show-portfolio`, `buy`, `sell`, `get-rate`.
2. Иерархия валют, доменные исключения, Singleton-настройки и хранилище, `log_action` и ротация логов.
3. API-клиенты, `update-rates`, `show-rates`, атомарное сохранение кэша и истории.
4. Полная проверка по критериям и демонстрация всех сценариев — следующий этап.

В `[tool.valutatrade]` задан TTL кеша 300 секунд. `get-rate` обновляет отсутствующие/просроченные данные, а `show-rates` явно помечает устаревшие записи. Время получения ответа хранится отдельно от времени котировки провайдера; бесплатный фиатный источник обновляет сами котировки раз в день.
